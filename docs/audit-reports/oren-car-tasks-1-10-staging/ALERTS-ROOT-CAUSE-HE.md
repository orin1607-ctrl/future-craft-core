## מה הייתה התקלה

### 1. השגיאה ב„צור התראה” — הרשאת RLS, לא באג בטופס

טבלת `custom_alerts` דורשת ש־`user_id` יהיה בדיוק המשתמש המחובר (`user_id = auth.uid()`).
כל הכותבים במערכת שלחו את **הפרופיל שמוצג על המסך**. כשמנהל־על צופה במערכת
כמנהל צי („צפייה כמנהל צי” / „צפה כמשתמש”), הפרופיל שמוצג הוא של מנהל הצי,
ולכן Postgres דחה כל שמירה:

```
42501  new row violates row-level security policy for table "custom_alerts"
```

זו הסיבה שאצלך התקבלה שגיאה גם בהתראת קצין רכב וגם בהתראה חופשית, מכל מסלול,
בזמן שאצלי הבדיקות עברו — הבדיקות הקודמות רצו בלי צפייה כמשתמש אחר.
ההוכחה מול Supabase Staging נשמרה ב־`alert-rls-probe/rls-probe.json`.

### 2. אותה תקלה הפילה גם את התראת הקצין מהתלת־חצי

הבדיקה עצמה נשמרה, אבל יצירת ההתראה נכשלה מאותה סיבה — ולכן במסך
„התראות ועדכונים” לא הופיעה „התראת קצין רכב”.

### 3. בדיקת תלת־חצי חדשה מחקה התראת קצין ידנית

בעת יצירת התראת קצין אוטומטית, הקוד כיבה **כל** התראת קצין של אותו רכב,
כולל התראה שיצרת ידנית — היא נעלמה מהמסך אחרי הבדיקה הבאה.

### 4. ביקורת אחת הופיעה כארבע שורות

לכל ביקורת נוצרת התראת הקצין עצמה ובנוסף תזכורות 30/7/1, וכולן נושאות את
הכותרת „התראת קצין רכב · מספר רכב” — כך שאותה ביקורת הוצגה ארבע פעמים.
