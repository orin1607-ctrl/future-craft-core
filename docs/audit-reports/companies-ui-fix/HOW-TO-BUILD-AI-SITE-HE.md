# מדריך הפעלה: בניית אתר AI (Staging בלבד)

מסמך זה מתאר את הזרימה בפועל במערכת כרגע, כולל מה עובד, מה דמו, ומה נדרש כדי להגיע לבניית אתר אמיתי.

## 1) איפה נכנסים
1. פותחים את `ai-marketing-platform.html` בסביבת Staging.
2. מהדאשבורד נכנסים לכרטיס **חברות ועסקים**.
3. בוחרים את הלקוח הרשמי: `dalia-c-official`.
4. לוחצים על **🧠 אסטרטגיית שיווק AI**.

## 2) על איזה כפתור לוחצים
1. במסך אסטרטגיה ממלאים/מאשרים פרטי עסק.
2. מתקדמים בשלבים עם **הבא**.
3. בשלב הניתוח לוחצים **▶ הפעל ניתוח AI**.
4. בשלב אישור לוחצים **✅ אשר ושלח לעוזרים**.

## 3) איך מריצים אסטרטגיית שיווק AI
1. השלבים הם: הכרת העסק -> חיבור נכסים -> ניתוח AI -> דוח ללקוח -> אישור.
2. הלחיצה על **הפעל ניתוח AI** מפעילה לוגיקת ניתוח פנימית ומייצרת דוח.
3. בסיום, הנתונים נשמרים ל-`localStorage` ונבנה `Business Context`.

## 4) מתי מופיע 🌐 צור אתר AI
1. הכפתור מופיע רק אחרי אישור הדוח בשלב 5.
2. התנאי בפועל: בלוק `exported` פתוח (אחרי `exportToPlatform` תקין).

## 5) איפה הוא מופיע
1. בתוך מסך **אסטרטגיית שיווק AI**, בחלק התחתון של שלב האישור.
2. ליד כפתורי ההמשך לעוזרים ופעולות משלימות.

## 6) מה קורה אחרי לחיצה על 🌐
1. נפתח **Website Builder Wizard** באותו מסך (מוסתר מסך האסטרטגיה הראשי).
2. נטען מידע מ-`dalia_biz` ו-`coco-business-context-v1`.
3. מוצגים KPI בסיסיים: חברה, שירות, אתר, תקציב.

## 7) איך עוברים את 7 שלבי Website Builder
1. **ניתוח עסקי ואפיון אתר** - קריאת ההקשר העסקי.
2. **מבנה אתר** - טיוטת Site Map.
3. **יצירת תוכן** - כותרות, מסרים ו-CTA.
4. **עיצוב וחווית משתמש** - עקרונות עיצוב בסיסיים.
5. **SEO On-Page** - טיוטת Title/Description/Keywords.
6. **תצוגה מקדימה** - Preview טקסטואלי פנימי.
7. **פריסה** - יצירת Payload שמירה והעברה להמשך עבודה.

## 8) מתי נוצר Preview
1. בשלב 6, אוטומטית בעת מעבר לשלב.
2. ה-Preview הנוכחי הוא תקציר תוכן/מבנה (לא רינדור אתר אמיתי).

## 9) מתי נוצרת תבנית אתר
1. כיום נוצרת **טיוטת Payload** בלבד (`structure/content/design/seo`).
2. לא נבנה בפועל HTML/CMS live ולא נוצר אתר מוכן לפרסום.

## 10) מתי מגיע שלב האישור
1. באסטרטגיה: שלב 5 (אישור והעברה).
2. ב-Builder: שלב 7 מסמן "מוכן לחיבור ל-CMS/Hosting בסביבת Staging".

## 11) מה עדיין דמו
- Website Builder כרגע דמו תפעולי מתקדם (wizard + payload).
- Preview הוא wireframe טקסטואלי/לוגי.
- אין בנייה אוטומטית של עמודים חיים ואין deploy אמיתי.

## 12) מה עדיין לא בונה אתר אמיתי
- אין מנוע יצירת עמודים אמיתי מתוך תבנית קבועה.
- אין חיבור כתיבה פעיל ל-CMS (WordPress/Wix וכו').
- אין pipeline מלא: Generate -> Render -> QA -> Approve -> Deploy.

## תשובות קצרות לשאלות העסקיות
- **האם Website Builder דמו בלבד?** כן, במצב הנוכחי הוא דמו תפעולי (Staging flow).
- **האם נוצר אתר אמיתי או רק מטא-דאטה?** כרגע נשמר בעיקר מטא-דאטה + payload תוכן/מבנה.
- **האם קיימת Template קבועה?** לא תבנית ייצור קשיחה אחת; יש מבנה ברירת מחדל, לא תבנית פרודקשן מלאה.
- **האם נבנים עמודים אמיתיים?** לא.
- **איפה רואים אתר בנוי?** אין URL של אתר בנוי אמיתי בשלב הנוכחי.
- **Preview אמיתי או Wireframe?** Wireframe/Preview לוגי בלבד.
- **מה נדרש לבנייה אמיתית?** מנוע תבנית קבועה + חיבור CMS + רינדור + אישור + Deploy.

## תכנון תבנית קבועה (סעיפים 6-7)
### מצב נוכחי
1. ממלאים נתונים -> מריצים אסטרטגיה -> מאשרים -> לוחצים 🌐.
2. Builder מייצר מבנה/תוכן/SEO כטיוטה ושומר JSON.
3. אין שכבת Template קבועה שמייצרת עמודים אמיתיים.

### מצב יעד
1. **Fill data** (שם, דומיין, שירותים, קהלים, מילות מפתח, צבעים, CTA, SEO).
2. **Strategy** (אישור אסטרטגיה עסקית ושיווקית).
3. **Approve** (אישור לקוח/מנהל).
4. **🌐 Build on Template** (תבנית בסיס אחידה לכל החברות).
5. **Real Preview** (רינדור עמודים אמיתי).
6. **User Approves** (אישור לפני פריסה).
7. **Deploy** (העלאה לסביבת יעד).

### עיקרון מוצר מומלץ
- תבנית אחת סטנדרטית לכלל החברות.
- ה-AI משנה רק שכבת תוכן/קונפיגורציה:
  - שם חברה, דומיין, שירותים, מילות מפתח, צבעים,
  - תוכן עמודים, סדר עמודים, CTA, SEO.
- כך מתקבלת יציבות UI + מהירות ייצור + יכולת QA סדורה.
