## 1) איזה דוח יופק לפני בניית האתר

יופק **Pre-Build Work Report** מקצועי ומלא, להורדה ואישור, שמחליף "סיכום קצר במסך" בשער מחייב לפני בנייה.

- שם מוצע: **`FULL_PRE_BUILD_WORK_REPORT`**
- מטרה: להגדיר במדויק מה בונים באתר החדש, למה, באיזה סדר, ועל סמך אילו נתונים.
- הדוח יהיה **מסמך החלטה** לפני `צור אתר`, ולא רק תצוגת מידע.

### תבנית הדוח (מיפוי 20 תחומי תוכן)

1. מצב האתר הנוכחי  
2. מה טוב באתר קיים  
3. מה חלש  
4. אילו עמודים משמשים מקור מידע  
5. אילו עמודים לא שווה להמשיך  
6. מילות מפתח לקידום  
7. מיפוי מילת מפתח לכל עמוד  
8. עמוד ראשון באתר החדש  
9. עמוד שני  
10. מה יש בכל עמוד  
11. כותרות לכל עמוד  
12. CTA לכל עמוד  
13. שירותים להצגה  
14. מטרות  
15. פעולות  
16. מה מתקנים  
17. מה בונים מחדש  
18. יעדים מספריים  
19. פלטפורמות עבודה  
20. סדר עבודה/ביצוע

## 2) איזה נתונים נכנסים לדוח

הדוח יאחד נתונים מכל המודולים הפעילים:

- **חברות ועסקים / אסטרטגיה:** `dalia_biz`, `coco-business-context-v1`
- **מטרות ופעולות:** `coco-business-strategy-actions-v1`, `workPlan.pages`, `workPlan.actions`
- **היסטוריה ודוחות:** `campaigns`, `activity`, KPI, keywords, assets
- **סריקה ותחרות:** crawl/work-plan + `competitors.json` (כשזמין)
- **Website Builder:** תכנון עמודים/keywords/sections קיים לצורך התאמה, אך עדיין לא build בפועל

---

## 3) איך הדוח מתחבר למטרות ולעוזרים

- הדוח מייצר **Brief מאושר אחד** לכל העוזרים במקום הקשר חלקי.
- המטרות בדוח הופכות ל-source of truth ל-`Goals` ו-`Agents`.
- רק אחרי אישור הדוח, העוזרים יקבלו מצב `approved_for_build`.
- הדוח מסמן מפורשות: **אתר דליה הישן = מקור מידע בלבד**.

---

## 4) איך הדוח מתחבר לפעולות

- כל פעולה בדוח תקבל שיוך לעמוד, קטגוריה, עדיפות, ותלות.
- סדר הפעולות ייוצא גם ל-workbench כדי לשמר רצף ביצוע.
- ייווצר פער ברור בין:
  - פעולות "תיקון קל" (אם בכלל)
  - פעולות "בנייה מחדש באתר החדש" (ברירת מחדל)
- סטטוסי פעולה יתויגו כ-`report_defined` לפני build.

---

## 5) איך הדוח מגדיר את עמודי האתר החדש

- הדוח יגדיר sitemap מלא לאתר החדש, בשליטה מלאה שלנו (מבנה/תוכן/SEO/מהירות).
- יוגדרו דפי ליבה, תתי-דפים, ותוכן לכל עמוד.
- עיקרון מחייב: **לא ממשיכים לפתח על האתר הישן**.
- שער התהליך יהיה:  
  `נתונים → מחקר → מתחרים → מילות מפתח → מטרות → פעולות → דוח מלא להורדה → אישור משתמש → בניית אתר`

---

## 6) איך הדוח מגדיר מילות מפתח לכל עמוד

- לכל עמוד יוגדרו:
  - מילת מפתח ראשית
  - 3-6 מילות תמיכה
  - כוונת חיפוש (מסחרי/מידעי/השוואתי)
  - התאמת CTA ומסר
- תישמר מטריצת `Page -> Keyword Set` כבסיס SEO ל-build.
- המיפוי יופיע גם בגרסת JSON לשימוש אוטומציה/בדיקות.

---

## 7) איך הדוח כולל את תוכנת/אפליקציית דליה

עמוד מרכזי מחייב באתר החדש: **תוכנת ניהול צי רכב של דליה**.

- שם עמוד מוצע: `תוכנת ניהול צי רכב לעסקים`
- ליבה תוכניתית לעמוד:
  - ניהול רכבים מרובים
  - תחזוקה מונעת ותקלות
  - ניהול נהגים
  - התראות ודוחות
  - התאמה לעסקים עם מספר כלי רכב
- הדף יוצב כעמוד אסטרטגי מוביל (לא הערת צד).
- יובהר בדוח: האתר החדש שיווקי ונפרד ממערכת הניהול התפעולית.

---

## 8) איך אחרי אישור הדוח בונים את האתר החדש

- אישור דוח יוצר `build_gate = approved`.
- רק אז נפתח שלב Website Builder לבנייה בפועל.
- מומלץ לשלב gate לפני הלחצן `צור אתר Preview מלא`.
- לאחר build:
  - preview מלא רב-עמודי
  - סבב תיקונים
  - אישור סופי
  - ורק אחר כך פריסה (לא חלק ממשימה זו)

---

## 9) מה עדיין דמו

- יצירת דוח מלא להורדה עדיין לא ממומשת end-to-end (PDF/HTML/JSON חתומים).
- יש "סיכום לפני בנייה" ב-Website Builder, אך הוא עדיין לא דוח מקצועי מחייב.
- זרימות אישור/ייצוא קיימות חלקית (UI + localStorage), לא כמנוע דוחות פורמלי מלא.
- אין כרגע Production flow במשימה זו (וכך צריך להישאר).

---

## 10) מה כבר אפשר לבנות עכשיו ב-Staging

- אפשר לבנות **Phase 1 תכנוני** מיידי:
  - מסך/שלב דוח מלא לפני build
  - ייצוא HTML + JSON
  - מצב `approved / pending` כשער לבנייה
- אפשר להוסיף ייצוא PDF ב-Phase 1.5 (דפדפן/שירות צד-שרת).
- אפשר להשאיר build עצמו ל-Phase 2 אחרי אישור דוח.
- אין למחוק אתר ישן, אין deploy לדומיין חי, אין פעולות Production.

## ארכיטקטורה מוצעת למודול הדוח

- מודול חדש מוצע: `public/ai-marketing/pre-build-work-report-module.js`
- אחריות מודול:
  1. איסוף נתונים מכל המקורות (Context + Goals + Actions + History + Reports + Crawl + Competitors + Builder seed)
  2. נרמול למבנה אחיד
  3. יצירת תוצרי דוח להורדה
  4. ניהול gate אישור לפני Build
- Aggregation contract מוצע:
  - `collectPreBuildInputs()`
  - `buildPreBuildReportModel(inputs)`
  - `renderPreBuildReportHtml(model)`
  - `exportPreBuildReportArtifacts(model)`

## פורמטי קבצים מוצעים לדוח

- **HTML** — קריא, עשיר, מתאים לשיתוף מהיר
- **PDF** — מסמך מקצועי חתום לאישור לקוח
- **JSON** — פורמט מכונה לשימוש עוזרים/בדיקות/אוטומציות

## מיקום הדוח ב-Flow (Gate)

אפשרות מומלצת:

- `אחרי פעולות` ולפני Website Builder build
- בתוך Website Builder: להוסיף שלב חדש לפני `צור אתר` בשם `דוח עבודה מלא ואישור`
- תנאי קשיח: בלי `report_approved=true` אין מעבר לבנייה

---

## תוכנית פאזות יישום

### Phase 1 — Staging Report Gate בלבד
- יצירת דוח מלא לפני build
- תצוגה + הורדה (HTML/JSON, PDF אם זמין)
- אישור משתמש מחייב
- ללא שינויי Production

### Phase 2 — Build אחרי אישור
- בניית אתר חדש רק לאחר gate מאושר
- preview מלא, תיקונים, אישור סופי
- עדיין ללא deploy חי כברירת מחדל במשימה

### Phase 3 — Hardening
- ולידציות, לוגים, עקיבות גרסאות דוח
- שיפור איכות SEO mapping ובדיקות QA

---

## עקרונות מחייבים במסמך זה

- דליה היא לקוח ראשון, האתר הקיים מקור מידע בלבד.
- לא מתקנים כרגע את האתר הישן כמוצר יעד.
- האתר החדש נבנה נפרד ממערכת ניהול דליה.
- אין Production, אין מחיקה, אין deploy חי בשלב הנוכחי.
