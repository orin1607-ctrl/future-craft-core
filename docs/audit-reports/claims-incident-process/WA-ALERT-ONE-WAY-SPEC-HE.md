# אפיון קצר לאישור — WhatsApp התראות חד-כיווניות

**סטטוס:** ממתין לאישור Owner — **לא יושם**  
**סביבה מיועדת:** Staging בלבד תחילה  
**עיקרון:** שינוי אחד בלבד · תשתית קיימת בלבד · אין מנגנון התראות חדש · אין מספר/אפליקציה חדשים

---

## מטרה

הודעת WhatsApp שנשלחת כ**התראת מערכת** (תקלה/תאונה דרך `notify-accident-email`) תהיה חד-כיוונית:

1. המשתמש לא מנהל שיחה עם הבוט דרך הודעת ההתראה.
2. **תשובה (Reply)** להודעת התראה **לא** מפעילה את Whatsapp Bot.
3. ההתראות נשארות התראות בלבד.
4. הבוט ממשיך לעבוד רק במסלול הצ'אט הייעודי (הודעה חופשית ל־`0546500305`, לא Reply להתראה).

---

## מה לא עושים

- לא בונים Edge / טבלה / UI התראות חדשים.
- לא מחליפים Gupshup app / מספר עסקי.
- לא משנים מסלול שליחת ההתראה (נשאר `notify-accident-email`).
- לא נוגעים ב-Production עד אישור מפורש אחרי Staging.
- לא חוסמים כל הודעה נכנסת מהמשתמש — רק תשובות להתראות.

---

## פתרון מוצע (קיים בלבד)

שני חיבורים קטנים על רכיבים שכבר במערכת:

### א) סימון יציאה — Edge קיים `notify-accident-email`

ב־`buildMessageText` (כבר קיים) להוסיף שורת זיהוי קבועה בסוף הודעת ההתראה, למשל:

`[התראת מערכת דליה — אין להשיב להודעה זו]`

- אותה פונקציית בניית טקסט שכבר שולחת תקלה/תאונה.
- אין API חדש, אין ערוץ חדש.

### ב) סינון כניסה — Make Whatsapp Bot קיים (`5797671`)

מיד אחרי Webhook (לפני AI / Gupshup 87), ב־**Router/Filter** שכבר קיים בתרחיש:

**אם** ההודעה הנכנסת היא Reply להתראה → **Ignore** (מודול `builtin:Ignore` כבר בשימוש בתרחיש) — בלי AI ובלי תשובה.

זיהוי Reply להתראה (לפי סדר עדיפות, על תשתית קיימת):

1. יש `context` / `replyId` / מזהה הודעה מקורית ב-payload של Gupshup → בדיקת HTTP ל-Supabase Staging על טבלה קיימת `incident_notification_deliveries`  
   (`channel=whatsapp` + `provider_message_id` = המזהה)  
   → אם נמצא: Ignore.
2. גיבוי: טקסט מצוטט / הקשר כולל את מחרוזת הסימון `[התראת מערכת דליה` → Ignore.

הודעה **חופשית** (בלי Reply להתראה) → ממשיכה למסלול הבוט כרגיל.

## זרימה אחרי השינוי

```text
תקלה/תאונה ב-UI
  → notify-accident-email (קיים)
  → WhatsApp עם סימון חד-כיווני
  → נשמר ב-incident_notification_deliveries (קיים)

Reply להתראה
  → Gupshup → Make Bot Hook (קיים)
  → Filter: התראה? → Ignore  ✅ אין תשובת בוט

«היי» / צ'אט רגיל (לא Reply להתראה)
  → אותו Hook
  → AI → Gupshup 87  ✅ בוט כרגיל
```

## מגבלות ידועות (שקיפות)

- ב-WhatsApp, אם המשתמש כותב הודעה חדשה **בלי** ללחוץ Reply על ההתראה — הבוט **כן** יענה (זה מסלול הצ'אט הייעודי — מכוון).
- חד-כיווניות מלאה «שום תשובה לא תיכנס לבוט אחרי התראה» בלי מספר נפרד **אינה** אפשרית ב-100% על אותו מספר; האפיון חוסם **Reply להתראה**, כפי שביקשת.
- DLR (`delivered`) נשאר בתרחיש DLR הקיים — לא דרך הבוט.

## תוכנית אימות אחרי אישור (Staging בלבד)

1. פתיחת תקלה ב-UI → התראה עם סימון.
2. Reply להתראה מ־0534338601 → Make רץ → Ignore → **אין** תשובת בוט.
3. הודעת «היי» חופשית → בוט עונה כרגיל.
4. Email / DB / מסכים — ללא שינוי התנהגות.
