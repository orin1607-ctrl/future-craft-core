## מה אומרת השגיאה

ב-Gupshup, **`Authentication Failed`** = הקריאה לשרת **לא אומתה** (401 / unauthorized).  
זה **לא** אומר שהאפליקציה שגויה (App ID כבר תואם), וגם **לא** אומר שהמפתח ב-Staging מת — הוא עדיין עובד.

כשלוחצים Create בטבלת API Keys, הממשק קורא ל-API של ניהול מפתחות. אם ה-session / התפקיד / סוג החשבון לא מורשים לפעולה הזו — מתקבלת בדיוק השגיאה הזו.

## תשובות לשלוש השאלות

### 1) האם החשבון מחובר בהרשאות חלקיות?

**סביר מאוד שכן (או session לא תקף).**

סימנים שמתאימים:
- רואים את האפליקציה + App ID (גישת צפייה)

### 3) האם API Keys מנוהלים ברמת חשבון ולא אפליקציה?

**שני רבדים (זה מסביר את הפער):**

| רובד | מצב אצלנו |
|------|-----------|
| **Account-level API key** (ישן) | Gupshup **הסתירו** מהממשק; עדיין עובדים. Staging כנראה על מפתח כזה → לכן שליחה עובדת, אבל ב-UI אין מה להעתיק |

כלומר: המפתח החי **לא חייב** להופיע בטבלה; יצירה חדשה היא פעולת **ניהול** שנכשלת על auth — לא הוכחה שהמפתחות «רק ברמת חשבון».
